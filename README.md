# 星际漫游 · Universe Explorer

面向儿童与亲子天文学习的浏览器太阳系探索器，支持简体中文、English、日本語。

当前方向：**自主托管、免账号、无外部运行时依赖、可离线探索**。应用是纯静态网站，三维渲染和飞行计算均在用户的浏览器中完成。

公开体验地址：[星际漫游 · Universe Explorer](https://panfeng-zeta.github.io/universe-explorer/)。代码仓库：[panfeng-zeta/universe-explorer](https://github.com/panfeng-zeta/universe-explorer)。首次打开需联网，等底部显示“可离线使用”后即可断网探索。

## 技术栈

| 层次 | 技术与职责 |
| --- | --- |
| 界面 | 原生 HTML、CSS、JavaScript ES Modules；响应式布局 |
| 三维 | Three.js **0.180.0**、WebGL 2、OrbitControls；行星、卫星、轨道、相机 |
| 物理计算 | 独立 JavaScript 模块；简化霍曼转移和开普勒运动 |
| 国际化 | 项目内中英日字典；不调用在线翻译服务 |
| 本地偏好 | `localStorage` 保存语言与画质偏好，不上传到服务器 |
| 离线 | Service Worker + Cache Storage；完整资源快照、完整性校验、版本更新 |
| 安装元数据 | Web App Manifest；添加到主屏幕的支持程度取决于浏览器 |
| 开发工具 | Node.js 22+；自带 HTTP 静态服务器和 `node:test` |
| 生产部署 | 任意可提供 HTTPS、正确 MIME 类型的静态网站服务器，例如现有 Nginx |

没有业务后端、数据库、用户账号系统、广告或分析 SDK；没有 GPT/OpenAI 模型 API、云端 AI 推理或实时星历 API 调用。生产服务器无需运行 Node.js，也无需安装 npm 依赖。Three.js 的固定版本已经放在 `dist/vendor` 中。

## 运行

### 本机运行，也适合完全没有互联网的环境

预先准备好本项目文件和 Node.js 22+，在项目目录运行：

```sh
npm run dev
```

打开 <http://127.0.0.1:5173/>。不需要 `npm install`，不需要联网，不需要登录。命令先生成离线资源清单，再启动只监听本机回环地址的静态服务器；终端保持运行即可使用。

不要直接双击 `index.html` 以 `file://` 打开：浏览器模块和 Service Worker 需要 HTTP(S) 环境。本机服务器仅供开发或离线本地使用，不作为公网生产服务器。

### 模拟部署在网站子目录

```sh
npm run dev -- --base /solar/
```

打开 <http://127.0.0.1:5173/solar/>。HTML、模块、贴图、离线缓存和安装元数据均使用相对路径，同一套文件可部署在域名根目录或 `/solar/` 等子目录。子目录入口必须以 `/` 结尾，服务器应将 `/solar` 重定向到 `/solar/`。

## 免登录与离线使用是两件事

| 场景 | 如何使用 | 条件 |
| --- | --- | --- |
| 在自己的网站免登录访问 | 浏览器打开公开 HTTPS 地址 | 首次访问需要网络；服务器不配置额外登录网关 |
| 从网站下载后断网使用 | 等待页面底部显示“可离线使用”，之后可断网刷新、重新打开 | 同一设备、浏览器和网站地址，离线缓存仍存在 |
| 从一开始就不连接互联网 | 将完整文件和 Node.js 提前复制到电脑，在本机启动 | 本机 HTTP 服务；无需访问外部服务 |

**第一次从网站打开不可能凭空离线下载。** Service Worker 会把页面、三语数据、三维库和全部天体贴图完整缓存。下载失败或环境不支持时会显示对应状态，不把未完成的下载标为“可离线使用”。失败时可点击状态重试。

联网重新访问时会检查新版本。完整新版本准备好后显示“新版已备好”，关闭本网站的所有标签再打开即可切换。旧页面不会在运行中突然换到半套新资源。

离线缓存不是永久安装：清除网站数据、无痕模式限制或系统存储回收可能删除缓存；此时需要联网重新下载。提前保存本机完整文件可以避免依赖浏览器缓存的长期保留。页面提供安装元数据，但不保证所有浏览器都会显示安装按钮。

技术依据：[MDN Service Worker 使用说明](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)、[存储配额与回收机制](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

## 部署到自己的服务器

服务器环境和域名确定后，再按实际环境落地。现在不要求更换服务器、增加数据库或引入云服务。

1. 在发布机运行 `npm run prepare:offline`，随后运行 `npm test`。
2. 将 **`dist` 内的全部文件**上传到静态网站目录，包含 `sw.js`、`precache-manifest.js`、模块、贴图、图标、Manifest 和许可证。
3. 配置 HTTPS，设置 `index.html` 为首页。Service Worker 需要安全上下文；开发时 `localhost`/回环地址是例外，普通局域网 HTTP 地址不等同于 localhost。
4. 让 `.js` 返回 JavaScript MIME、`.webmanifest` 返回 `application/manifest+json`；不存在的脚本应返回 404，不能返回首页 HTML。
5. 对稳定文件名使用重新验证缓存策略，例如 `Cache-Control: no-cache`。不要把 `sw.js`、离线清单、首页和模块设成永久不可变缓存。
6. 尽量采用整目录原子切换。资源带 SHA-256 完整性校验，上传不完整会使新缓存安装失败，保留可用的旧版本；不能依靠边上传边让用户安装来发布。
7. 不要让托管平台、CDN 或优化插件自动改写 JS/HTML/CSS 的字节；改写后的文件会与离线清单的完整性校验不一致。正常 HTTP gzip/Brotli 传输压缩不影响校验。
8. 根据下方验收清单，在真实域名上完成首次安装、断网刷新和更新测试。

提供 [Nginx 独立域名配置示例](deploy/nginx.conf.example)。其中域名、证书路径和磁盘目录都是占位值，不要直接覆盖正在运行的网站配置。若嵌入现有网站的子目录，应把 `dist` 的内容放在该子目录对应的文档根目录中，并让 Service Worker 只控制该路径。

**每次修改 `dist` 文件后，都要重新生成离线清单，再一起发布。** `npm run check:offline` 会发现文件变更和清单不匹配；版本标识由所有发布文件内容生成，不需要手动改版本号。

## GitHub Pages 公开部署

本项目提供 [GitHub Actions 发布流程](.github/workflows/pages.yml)。推送到 `main`，或在 Actions 中手动运行 **Deploy GitHub Pages** 后，流程会使用 Node.js 22 重新生成离线清单、执行全部测试，再将 **`dist` 的内容**发布到 GitHub Pages。没有 npm 依赖需要安装；测试失败时不会发布。

首次设置：在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。公开仓库可使用 GitHub Free 的 Pages；仓库代码也会公开。网站访客无需 GitHub 或 GPT 账号，服务器端不运行 Node.js。具体行为见 [GitHub 官方部署说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

Pages 的项目地址通常为 `https://<账号>.github.io/<仓库名>/`；以成功部署时显示的地址为准。应用的相对路径和 Service Worker 作用域支持这种子目录。首次联网打开后，等待“可离线使用”，之后在同一设备和浏览器中即可断网使用。安装到主屏幕也使用这个公开网址，与旧 OpenAI Sites 演示、本机 `127.0.0.1` 地址分别独立。

工作流会在 Linux 上按实际发布字节重新计算资源完整性，避免本机与 CI 换行格式差异影响离线安装。Pages 不提供自定义 Nginx 缓存配置；新资源下载或完整性检查失败时，应用保留已安装的旧版，联网后可重试。网站发布目录不包含开发脚本、测试或旧 Sites 配置。

## 科学模型与当前限制

数值使用 NASA/JPL 的平均半径、轨道半长轴、恒星公转周期和赤道重力。巨行星重力参考云层，不是固体表面。

画面中的天体大小、轨道距离分别压缩；轨道为圆形共面近似，初始位置是示意位置。日期只是模拟进度，不是当天实时星历。月球以外的卫星颜色为示意，海卫一公转为逆行。

太阳和八颗行星采用各自的恒星自转周期与轴倾，自转和公转共用模拟时间；近景显示自转周期、轴倾数值与轴线。金星、天王星用完整的大于 90° 的轴倾表达逆行，不再把周期取负而重复反转。轴倾方向在空间中保持固定，土星环处于其赤道面。显示坐标以 +Y 为黄道北侧，公转使用 `(cos a, 0, -sin a)`，使地球贴图北极与自转方向一致；飞行路径使用同一坐标约定。默认 1 天/秒；较高时间倍率可能产生自转混叠，应减速或暂停观察。

月球及另外十九颗所选卫星采用理想同步模型：每公转一周自转一周，同一本地表面方向持续朝向母行星，海卫一保留逆行。卫星轨道与自转轴简化为共面、零轴倾，不模拟月球天平动；贴图本初经度未按真实星历校准。

总览使用位于太阳中心的点光源，近景使用随所在行星公转方向变化的平行太阳光；转动相机不会改变受光方向。为便于观察，保留微弱环境光，不按真实距离平方衰减亮度。土星环着色、光晕仍为示意，不模拟遮挡阴影、日月食、真实历元极点方向或大气差异自转。可用于昼夜、轴倾和同步自转的几何演示，**不提供精确月相、季节日期或食象预报；本轮未增加独立课程界面**。

自转参数来源为 [NASA 行星资料表](https://nssdc.gsfc.nasa.gov/planetary/factsheet/)；土星更新为 [Cassini 环震学估计的 10 小时 33 分 38 秒](https://www.jpl.nasa.gov/news/scientists-finally-know-what-time-it-is-on-saturn/)，天王星更新为 [Hubble 2025 测量的 17 小时 14 分 52 秒](https://science.nasa.gov/missions/hubble/hubble-helps-determine-uranus-rotation-rate-with-unprecedented-precision/)。太阳用约 16° 纬度的代表周期，巨行星采用代表性的内部自转周期，并非所有云层都以相同角速度运动。完整来源与约定见 `dist/CREDITS.txt`。

飞行计算使用真实 AU 和太阳引力参数，假定理想窗口。动画的行星角速度由同一太阳引力参数推导，飞船按开普勒方程推进并与目标会合；压缩后的画面轨迹不是按真实比例绘制的椭圆。Δv 不含逃逸、捕获、地面发射、着陆、倾角及其他天体引力。飞行过程中普通模拟时钟保持不变，飞行进度单独显示。

## 平板性能与画质

页面底部可切换“标准 / 省电”，偏好保存在当前浏览器。首次访问时，主指针为触控的设备默认省电；已保存的选择优先。切画质保留天体、相机、模拟时间、暂停状态和飞行进度。

| 配置 | 标准 | 省电 |
| --- | --- | --- |
| 像素比上限 | 1.7 | 1 |
| 球体分段 | 72 × 48 | 32 × 20 |
| 星点数量 | 2500 | 700 |
| 各向异性上限 | 8 | 2 |
| 渲染帧率上限 | 60 | 30 |
| 云层与光晕 | 开启 | 隐藏 |

- 近景只创建选中天体及其卫星；总览按需创建太阳和八行星，已创建对象继续复用。
- 贴图按资源复用，地球云层的颜色与透明度共用同一个纹理对象；共享几何与纹理统一释放。
- 暂停且相机阻尼收敛后停止请求绘制；切换天体、语言、画质、显示选项、缩放及纹理加载完成都会唤醒。
- 标签页隐藏时取消调度，恢复后从原进度继续，不把后台经过的时间补入模拟。
- 飞行到达后发送最终进度并停止空转；图鉴和离线缓存仍保留完整资源下载，优化主要降低场景创建和 GPU 开销。

以上是工作量上限与代码行为，不代表每台平板都能达到标注帧率；实际设备的帧率、功耗和温度尚待测量。
